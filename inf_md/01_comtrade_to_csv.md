# Этап 0: Конвертация COMTRADE → CSV

## Исходный формат
COMTRADE (IEEE Std C37.111) состоит из двух файлов:
- `.cfg` — конфигурация (имена каналов, единицы измерения, частота дискретизации)
- `.dat` — бинарные или ASCII-данные отсчётов

## Выходной формат CSV
После конвертации `tools/data_comtrade_to_csv.py` каждый CSV-файл содержит:

| Столбец | Описание | Единицы |
|---|---|---|
| `time` | Время от начала записи | с |
| `CT1IA` | Ток фазы A | А |
| `CT1IB` | Ток фазы B | А |
| `CT1IC` | Ток фазы C | А |
| `S1) BUS1UA` | Напряжение фазы A | кВ |
| `S1) BUS1UB` | Напряжение фазы B | кВ |
| `S1) BUS1UC` | Напряжение фазы C | кВ |
| `distance_km` | Расстояние до КЗ | км (константа по файлу) |
| `fs_hz` | Частота дискретизации | Гц (константа по файлу) |

## Математическая модель сигнала в CSV
Каждый канал — дискретизированный во времени сигнал:

```
x[n] = x(t=n·Ts),  n = 0, 1, ..., N-1
```

где:
- `Ts = 1/fs` — период дискретизации [с]
- `N` — общее число отсчётов в файле
- `fs` — частота дискретизации [Гц]
<!-- 
## Пример -->
При `fs = 5000` Гц и `N = 2000` отсчётов:
- `Ts = 0.0002` с = 0.2 мс
- Длительность записи: `T = N·Ts = 2000 · 0.0002 = 0.4` с = 400 мс

## Примечание
- `fs_hz` записывается в каждую строку CSV как константа
- Это позволяет `dataset.py` читать `fs` напрямую из файла
- Для старых CSV без `fs_hz` используется fallback `cfg.SAMPLING_FREQ_HZ`
